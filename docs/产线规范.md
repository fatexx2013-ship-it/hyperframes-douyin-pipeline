- 本文档定位：**产线工程规范的唯一真源**。四件套的用途/命令/使用时机、TTS 选线规则、交付前必跑清单均以本文为准；Marvis 技能（`video-pipeline-douyin`）与 MiMo Code 技能（`video-pipeline-mimo`）是本文的镜像速查，口径冲突时以本文为准。

## 一、产线四件套

四项能力在同一次升级（2026-09-24）中落地，来源为 EigenFlux 交换资料（通用参数漂移清单 10 项 + 两级负控执行节奏 + 分阶段峰值记录法）。

| # | 组件 | 落点 | 一句话职责 |
|---|---|---|---|
| 1 | 参数合同 | `config/param_contract.json` | 定义 10 个漂移字段的口径与稳定级别，是判定的唯一依据 |
| 2 | 参数快照与漂移比对 | `scripts/param_contract.py` | 从真实成片抽实际参数 → manifest；manifest 互比 / 对合同校验 |
| 3 | 两级负控 | `config/negcontrol_cases.json` + `scripts/negcontrol.py` | 用已知答案的用例证明检测器有效；素材绑定版本留档 |
| 4 | 分阶段资源峰值 | `scripts/resource_peaks.py` | 分阶段采统一内存 RSS 峰值，定位是哪一阶段顶到上限 |

### 核心设计原则

1. **校验点设在拼接/交付边界，不在单段出口**。清单明确指出漂移"单镜头看不出来，只在跨镜头或长段落拼接边界暴露"。
2. **两级稳定级别**：
   - **不变量级（invariant）**：fps 与取整策略、画幅方向、音频采样率、模型与权重版本 → 漂移判 **FAIL 阻断**
   - **探索级（exploratory）**：片段时长、色彩空间、TTS 采样参数、精度模式、VAE 等价项、分块与降级 → 漂移判 **WARN**，进周回归清单
3. **合同必须用真实成片回灌校正**。首版 1.0.0 把交付音频口径写成只允许 44100Hz/1ch，实测线上正常成片 `story/howtolivebetter/douyin_final.mp4` 为 44100Hz/2ch（含 BGM 立体声混音）——不校正会把正常交付误判为阻断。1.0.1 已修正。**任何字段口径变更都必须递增 `contract_version` 并追加 changelog。**

## 二、命令速查

所有命令在产线根目录 `/Volumes/PSSD/抖音视频` 下执行。

### 2.1 参数合同：`param_contract.py`

```bash
# snapshot —— 从一次真实产出抽取实际参数，产出 run manifest
python3 scripts/param_contract.py snapshot \
  --video output/xxx/douyin_final.mp4 \
  --story-dir story/xxx \
  --label "20260924-xxx" \
  --out reports/artifacts/manifest_xxx.json
# 可选：--model-dir（默认本地 Qwen3-TTS 模型目录）、--deep-hash（模型权重逐文件内容哈希，慢但最严）、--contract

# diff —— 两份 manifest 逐字段比对
python3 scripts/param_contract.py diff \
  reports/artifacts/manifest_baseline.json \
  reports/artifacts/manifest_current.json \
  --json-out reports/artifacts/diff_xxx.json

# check —— 单份 manifest 对合同口径校验（交付前必跑）
python3 scripts/param_contract.py check \
  reports/artifacts/manifest_xxx.json \
  --json-out reports/artifacts/check_xxx.json
```

**参数来源**：视频侧走 `ffprobe`（`r_frame_rate` 取有理数精确值、width/height、color_space/transfer/primaries、audio sample_rate/channels、format.duration）；配置侧读模型目录指纹（sha256）、量化精度（模型目录 `-8bit` → int8）、渲染配置 `hyperframes.json`、渲染/处理日志中的降级标记。

### 2.2 两级负控：`negcontrol.py`

```bash
# 不变量级全量跑 —— 任何参数表版本升级 / 权重升级，变更即验证
python3 scripts/negcontrol.py run --level invariant

# 探索级抽跑 —— 每周一次全量回归
python3 scripts/negcontrol.py run --level exploratory

# 全部用例
python3 scripts/negcontrol.py run --level all

# 素材留档指纹校验（用例绑定的 sha256 是否与实际素材一致）
python3 scripts/negcontrol.py verify-materials

# 查看两级节奏与上次结果
python3 scripts/negcontrol.py status
```

用例结构统一为 **触发条件 → 输入 → 期望判定 → 必填字段**，素材与用例**绑定 sha256 版本留档**（素材换版必须重新标定，否则下一轮变更时不知道该拿什么做对照）。

### 2.3 分阶段资源峰值：`resource_peaks.py`

```bash
# 监控一条命令，按 #STAGE 标记分阶段采进程树 RSS 峰值
python3 scripts/resource_peaks.py monitor \
  --name render_xxx --rss-limit 24GB --interval 0.05 \
  -- bash -c '#STAGE loading …; #STAGE composing …; #STAGE audio …; #STAGE upsampling …'

# 查看档案 / 两份档案阶段峰值对照
python3 scripts/resource_peaks.py show --profile reports/peaks/render_xxx.json
python3 scripts/resource_peaks.py compare --baseline a.json --current b.json
```

被监控命令向 stdout 打印 `#STAGE <name>` 即切阶段。产出：各阶段峰值 RSS + 整段峰值 + 上限百分比 + 降级关键词扫描结果。

## 三、退出码语义（脚本化门禁依赖此表）

| 脚本 | 退出码 | 含义 |
|---|---|---|
| `param_contract.py` | **0** | OK 或仅有 WARN（WARN_ONLY 不阻断） |
| | **1** | 用法错误（USAGE_ERROR） |
| | **2** | **不变量级漂移（INVARIANT_FAIL）—— 必须阻断交付** |
| `negcontrol.py` | **0** | 全部用例达到期望判定 |
| | 非 0 | 至少一条用例未达期望（检测器失效或素材指纹不符） |
| `resource_peaks.py` | **0** | 峰值在上限内，未触发降级判定 |
| | **2** | 峰值超上限（降级风险），需定位到具体阶段 |

**判定语义**（来自合同 `verdict_rules`）：
- `FAIL` —— 不变量级字段偏离合同口径，或与基线 manifest 不一致
- `WARN` —— 探索级字段偏离，不阻断，但必须登记进周回归清单
- `SKIP` —— 该字段本次没有对照证据（既无固定期望值，也无基线 manifest），**不计入判定，但要在报告里如实列出，不得读作"通过"**

## 四、交付前必跑清单

每次成片交付前，按顺序执行：

| # | 动作 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 抽本次成片快照 | `param_contract.py snapshot --video <成片> --story-dir <story 目录> --out reports/artifacts/manifest_<本次>.json` | 生成 manifest |
| 2 | 对合同校验 | `param_contract.py check reports/artifacts/manifest_<本次>.json` | **无 FAIL**（exit 0；出现 exit 2 必须修完再交付） |
| 3 | 与上一版基线比对 | `param_contract.py diff <基线 manifest> <本次 manifest>` | 无不变量级漂移 |
| 4 | 负控素材指纹校验 | `negcontrol.py verify-materials` | exit 0 |
| 5 | TTS 选线确认 | 见第五节判据 | 判定结果写入成片备注 |
| 6 | 资源峰值（链路有改动时） | `resource_peaks.py monitor --name <本次> --rss-limit 24GB -- <渲染命令>` | 峰值在上限内 |

**节奏类动作**（非每次）：
- **参数表版本升级 / 权重升级 → `negcontrol.py run --level invariant`（全量，变更即验证）**
- **每周一 → `negcontrol.py run --level exploratory`（探索级抽跑）**

### 已知口径（截至 v1.0）

- 交付分辨率/画幅：1080x1920 / 9:16（不变量级，强制 scale+pad 并 setsar=1）
- 交付帧率：30fps（不变量级）。**实测历史成片 `github_trending.mp4` 为 25fps，属真实漂移，已抓出**
- 交付音频：44100Hz；纯配音 mono、含 BGM 立体声混音为 2ch 均接受（不变量级）。**实测 `news-dialogue-0817-final.mp4` 为 48000Hz/2ch，说明绕过了 `post_process.py` 统一音频后处理，已判 FAIL**
- TTS 出口口径：24000Hz / mono
- 工具链 pin：ffmpeg 9.0.1、ffprobe 9.0.1、hyperframes 0.8.13、node v26.8.1
- 编码链：h264_videotoolbox / libx264 / High@4.2 / yuv420p / 8M 视频码率 / 128k 音频码率

## 五、TTS 选线规则（硬性默认）

> 本节为用户最新硬性默认，**逐条执行，不得改写口径**。

### 5.1 三条默认（不可改写）

| # | 规则 | 口径 |
|---|---|---|
| 1 | **默认引擎** | 仍是本地**千问3 TTS（Qwen3-TTS 12Hz 1.7B Base 8bit，本机 MLX 链路）**，模型目录 `~/Projects/qwen3-tts-apple-silicon/models/Qwen3-TTS-12Hz-1.7B-Base-8bit`；**不启用云端 TTS** |
| 2 | **双女生对话** | 沿用**既有双人流程**（`scripts/gen_guimi_dub.py` 那套），**不改动** |
| 3 | **单人女声 / 口播** | 启用**「慵懒御姐音」**，参照 `output/voice_tuning_fg_20260917_045103/` 下已有的 F / G 双版参数 |

关于规则 1 的边界：既有脚本中存在的 Edge TTS 兜底分支（`generate_qa_video.py:generate_edge_tts`、`scripts/edge_tts.py`）**属历史遗留，默认不启用**；若本地 Qwen3-TTS 链路失败，应报错并停下来修链路，而不是自动切云端。

### 5.2 Agent 自动判断走哪条线 —— 可执行判据

> 目标：不写"自动判断"四个字。以下判据可机械执行，判定结果必须写入成片备注（建议字段 `tts_line: duo | solo-yujie`）。

**第一步：抽对白句集合 D**

对文案做机械提取：
- 形如 `名字：台词` / `名字:「台词」` 的行 → 直接判为对白句，且**显式给出说话人**
- 含成对引号（`""` / `「」` / `''`）的句子 → 判为对白句，说话人待第二步推断

**第二步：数说话人数 N**

- 有显式说话人标记 → `N = 去重后的说话人个数`
- 无显式标记 → 按**轮替语义**推断：相邻引号段落互相回应（一问一答、指称对方为"你"、语义上构成反驳/追问）→ 视为**不同说话人**；连续引号段落是同一人一气说完 → 视为**同一说话人**

**第三步：判定（按顺序命中即返回）**

| 优先级 | 条件 | 判定 |
|---|---|---|
| 1 | `N ≥ 2` 且对白在文中**交替出现**（存在 ≥1 次说话人切换） | **走双人线** → `scripts/gen_guimi_dub.py` |
| 2 | `N ≥ 2` 但**对白占比 < 10%** 且全篇主体为第一人称叙述/口播 | **走单人线**（对白极少不足以构成对话节目形态） |
| 3 | `N ≤ 1`（仅单人对白、或引用他人话但不需要用不同音色区分说话人） | **走单人线** → 单人 TTS + 慵懒御姐音 |
| 4 | 边界/判不准 | **默认走单人线**（成本低、可复听校正），并在成片备注标注 `tts_line: solo-yujie (待确认)` |

**第四步：双人线的适用范围限定**

- 本规则中的"双人流程"仅适用于**两个说话人均为女声**（既有脚本即御姐音 林悦 + 少女音 苏苏）；
- 若文案出现**男声角色**、或对话人数 **≥3**，**不属本规则范围**，必须停下回报用户确认，不得自行套用双人流程。

**第五步：判据自查（必须至少满足其一才算"是对话"）**

- ✅ 文案中存在**多角色轮替对白**（说话人交替出现）
- ✅ 引号对白**需要区分说话人**才能真正听懂（一问一答、争执、互相指称）
- ❌ 仅仅是"引用了某人说过的一句话"→ 不是对话，走单人线
- ❌ 只是旁白里出现引号强调词（如"所谓'护城河'"）→ 不是对话，走单人线

### 5.3 单人线「慵懒御姐音」参数（F / G 双版）

参照：`output/voice_tuning_fg_20260917_045103/御姐音F-G双版优化报告_20260917.md`（基准参考音 `yujie_thoughtful.wav`，F0 中位 163.0Hz / 谱质心 1895Hz）。

**两版共用（硬约束）**

| 环节 | 参数 |
|---|---|
| 参考音 | `~/Projects/qwen3-tts-apple-silicon/voices/yujie_thoughtful.wav`（6 情绪参考音：thoughtful / excited / surprised / calm / playful / serious） |
| 静音修剪 | 温和档 `-52dB / 0.30s`：仅把**句内**长于 0.30s 的静音截到 0.30s；≤0.30s 的短停顿原样保留 |
| 句首前导 | 保留 **0.12s**（句尾 0.080s） |
| 语速/变调 | speed=1.0，不做整体变调 |
| 输出格式 | MP3 192kbps / 24kHz / 单声道（与成片人声轨一致） |
| **硬指标** | **句内静音 ≥0.40s 的档位必须为 0**（A 版原有 20 处"说一半就断"，F/G 均为 0） |

**两版差异**

| 维度 | **G 版（逐句·对比停顿）默认** | **F 版（合并单元·动态停顿）备选** |
|---|---|---|
| 合成单元 | 逐句（与既有产线颗粒度一致，时间轴无需重算） | 同场景相邻句合并，上限净语音 ≤9.0s 且 ≤2 句 |
| 句间停顿 | 逗号 0.25s / 句末 0.75s / 段落 1.20s | 逗号 0.35s / 句末 0.60s / 段落 0.90s |
| 听感 | 抑扬分明、呼吸感强、段落层次清晰 | 推进感强、信息连贯、更紧凑 |
| 时长 | 与 A 版等长（示例 88.65s） | 比 A 版短约 4.61s（示例 83.97s） |
| 适用 | **默认**：时长宽裕、要层次感 | 成片时长吃紧（如需压 90 秒）时改选 |

**选版规则**：默认用 **G 版**（逐句颗粒度与既有逐句 TTS + 卡片时间轴天然对齐）；仅当配音总时长超出目标成片时长时改选 **F 版**（可省约 4.6s，但**需同步重算卡片时间轴**）。

**发声质检（两版共同）**：以 10ms 帧、-52dB 判决统计停顿分布；逐段 F0 中位若 **> 1.3× 全曲中位** 判定音色漂移，触发重合成或音高回拉（+1～+2 半音）。样例文案的 F0 中位：F 版 178.8Hz（阈值上限 232.4Hz）、G 版 174.7Hz（阈值上限 227.1Hz）。

### 5.4 双人线（沿用既有流程，不改动）

- 脚本：`scripts/gen_guimi_dub.py`（复用 `generate_qa_video.py` 的 Qwen3-TTS 管线）
- 角色映射：**林悦 = 御姐音（`yujie_answer` + 情绪）/ 苏苏 = 少女音（`shaonv_question`）**

- 本流程**保持原样**，不因本次规范建立而改动

## 七、已知局限（诚实标注）

1. **RSS ≠ 显存**：macOS 统一内存存在压缩与 swap，RSS 会低估真实内存压力；且不含 GPU/ANE 侧占用。未命中降级关键词不等于没降级。
2. **轮询采样会漏峰**：默认 0.05s 间隔，短于采样间隔的瞬时峰值可能漏掉；短阶段（如 audio 0.08s 仅 2 个样本）置信度低。
3. **colorspace 只能判 WARN**：实测素材中 `unspecified` 普遍存在，脚本无法区分"实际正确但没写 tag"与"真的错"。根治要在编码侧显式 `-colorspace bt709 -color_primaries bt709 -color_trc bt709`。
4. **配置侧字段依赖命名与日志规范**：`precision_mode` 依赖模型目录 `-8bit` 命名；`chunk_size_auto_downgrade` 依赖日志中出现降级关键词；`sampler_steps_cfg_seed` 当前只能读到 `explicit=false`（TTS 推理尚未显式传入采样参数）。
5. **TTS 阶段与端到端渲染的峰值未实测**：现有峰值档案来自真实素材 + 等价 FFmpeg 负载。
6. **SKIP 不等于通过**。
7. **排期未接入调度器**：两级节奏的命令已提供，目前需手动触发。

### 1. 三锚校验（针对"执行成功但内容退化"）

| 锚 | 校验对象 | 判据 | 失败语义 |
|---|---|---|---|
| 字节锚 `byte_anchor` | 投递完整性 | `declared_bytes` == 实际字节数 | FAIL「投递截断」 |
| 条数锚 `item_anchor` | 载荷完整性 | 声明条数 == 实际条数；`items_path` 支持多段 `+` 求和（如 `rows+extended_rows`） | FAIL「载荷缺口」 |

锚未声明对照值 → 该锚 **SKIP（不计通过）**；任一锚断链 → 该段 FAIL。

### 2. 「未更新 ≠ 执行失败」（OCFANE）

- **零退出码 + 空消息不得判为健康** —— 二者在观测上无法区分"无更新"与"执行失败"，须补已核对证据（status / 产物留档），否则判 UNKNOWN。
- 「未更新」是合法终态，但**必须有证据**；无证据不得记为健康（health 段的 `evidence_complete` 字段标记证据是否齐备）。

### 3. 计量口径（ruqiwg 四约束）

- **UNSET ≠ EMPTY**：UNSET = 未上报，**不进任何分母**，也不得读作 EMPTY / 0；EMPTY = 已上报且为空。
- **绑定 universe 版本**：每条回执登记 `universe_version`，与当前版本不一致 → **不可比**（防静默漂移），单列 `incomparable` 而非计入分母。
- **INCOMPLETE 只入尝试分母**：尝试分母 = COMPLETE + INCOMPLETE，成功分子只算 COMPLETE；INCOMPLETE 必须带**枚举原因码**，缺失即报问题（`incomplete_reason_tally` 汇总原因码分布）。

### 4. 读级 / 内容级两列新鲜度（AI-Film-Studio）

- **读级新鲜**（`read_level_freshness`）证明"检查确实被执行"；**内容级新鲜**（`content_level_freshness`）证明"内容确实变了"。
- 「无事件上报」与「无事件发生」在观测上同形，必须分列判定：
  - FRESH / FRESH → `EVENT_OBSERVED`（有事件上报）
  - FRESH / ABSENT → `NO_CONTENT_CHANGE`（已观测、确认无变化）
  - STALE / ABSENT → **`UNOBSERVED`（无事件上报）**，不得读作"无事件发生"，必须补证据

### 1. 静默改写判定（`silent_rewrite`，检查项 I）

判据是「**是不是被静默改写**」而不是「改了什么」：调用方**显式指定**的变化 → 允许降级 + 强制标记（`reason_code` / `source`）；**未指定而被升级或默认值静默改写**为另一档（采样器与调度器标识 / 精度与量化档 / 文本规范化器版本）→ **升格硬停**。把「未指定」与「显式指定为默认档」合并后，这一档就再也查不出来。
负例：`precision_quantization` 显式值被删除、由默认档补齐 → 必须判红（升 `hardstop`），不得只记降级。

### 2. 判据身份三格与版本换代出桶（`criteria_identity`，检查项 J）

判据须带 **version + issuer + effective_from** 三格。缺 `effective_from` → 事后复算旧产物判不清该用哪版判据，判 `UNKNOWN`，翻案率亦无法跨周期比较（会悄悄退化成「每期各算各的」）。
**版本换代本身记一条独立事件、单独出桶**，不并进漂移计数——否则一次换代会让当期漂移读数整体跳一次，看着像系统性劣化。
负例：三格缺生效起点，或换代事件并入漂移计数。

### 3. 未声明 ≠ 默认（`zero_declared_vs_default`，检查项 K）

「未声明（UNSET）」与「显式声明为默认档」是两个取值，不得合并；UNSET 既不得读作 0，也不得读作通过。
负例：`declared=false` 的默认值被读成「已声明」。

### 4. 挂起年龄分布（`pending_age_distribution`，检查项 L）

每条挂起项绑 **挂起起始时刻 + 所属重跑成本档**；报告须给 **P50 / P90 / P99** 分位——「一撮老的压着」与「一批新的涌入」处置动作完全不同，只数条数看不出来。
越过容忍度的阈值基数取 **当轮新增**挂起数，**存量另出桶**：拿存量做基数会随时间自然老化而读数自动变好，正好把积压洗掉（与第 5 条同形）。
负例：阈值基数写成存量，或只报分位而不绑起始时刻。

### 5. 翻案率分母口径（`overturn_denominator`，检查项 M）

翻案率分母只算「**已人工复核过的拒绝**」，未复核的挂起项单独出桶、不进分母；否则积压越多、读数越健康。
负例：`evaluations` 含未复核项；或按裸 `rule_id` 跨版本求和。

### 6. 依赖版本三段（`dependency_version_triple`，检查项 N）

版本拆三段：**来源版本（source_version）+ 内容版本（content_hash）+ 已加载版本（loaded_version）**。三者只对上两段最危险——来源变了而实际加载的还是旧的，账面「版本一致」、产出口径已不同。**只锁路径不锁版本等于没锁**。
负例：只声明两段、缺已加载版本。

### 7. 时基三格（`timebase_triple`，检查项 O）

时基字段须同时声明 **单位（unit）+ 时钟域（clock_domain）+ 取整时机（rounding_moment：写入即取整 / 读取时取整）**。同一数值被两段各自取整一次，每段单看都合法，累积差只在成片对齐时才暴露；缺取整时机按「时基单位不一致」处理。
负例：缺 `rounding_moment`。

### 8. 分页第三态与终止分账（`pagination_completeness`，检查项 P）

- `has_more=true` 而下一页入口不可达 → 第三态 **unreachable**（既非「已取尽」也非「无数据」），不得折叠进「取尽」参与最终记账；完整性声明与游标签发必须同源。
- 合并判空须加**去重断言**：第二轮条目键与第一轮重叠即判「未推进」，防服务端重放第一页被误判成取尽。
- 轮数上限必须配「**未取尽**」出口：终止原因分账，「拉空」与「拉到轮数上限」是两个不同终止原因。
负例：`has_more=true`、`continuation` 缺失却判「取尽」。

### 9. gate 三数同行与跳过发起侧记账（`gate_three_numbers`，检查项 Q）

gate 指标（比值类尤甚）必须**三个数同行落盘：分子 / 分母 / 显式跳过数（须带原因码）**，缺任一即判 **UNKNOWN**、不判 PASS；比值类拆成分子、分母两条独立序列各自告警。
**跳过必须由发起侧记账**，不得在应答侧去重后登记——显存紧张时渲染器降级到简化节点、出口回执仍是 0，只有把降级事件单独计成一个分母才暴露。
负例：只有比值、缺三数之一，或跳过记在应答侧。

### 10. 降级由产物侧判定（`degrade_product_side`，检查项 R）

「有没有走降级」不由链路自述：**期望产物清单 − 实际落盘产物**，非空即记降级；链路自报路径、自报 `as_of` 一律降级为**未观测**，不单独充当健康信号；降级事件应单独成流、签发方落在被测链路之外。
负例：以自报 `degraded=false` 作为唯一健康证据。

### 11. 失败域四段分桶（`failure_domain_buckets`，检查项 S）

漂移项按 **前置素材 / 渲染 / 编码 / 合成** 四段分桶：① 前置素材＝输入契约没钉死（帧率、时长、字幕时间码两次读取不一致且不报错；缓存冷热由运行方自报）；② 渲染＝非确定段边界未声明（含 GPU 或随机种子的步骤被算进「可复现」）、只锁路径不锁版本；③ 编码＝容器代理冒充内容证据（帧数与文件存在性只是代理，结构合法但被截断的产物按完整通过）；④ 合成＝随机源不可注入种子、超集产物（多一轨音轨或字幕）能过全部「应存在」型断言。
配套要求：断言集里至少留一条「**本应不存在**」。
负例：四段缺段，或缺少「本应不存在」断言。

### 12. 共享故障域反例（`shared_fault_domain`，检查项 T）

独立检查若与被测共享故障域，就不是独立证据：① 探针与被测共用同一上游源（配置 / 时钟 / 证书由同一流水线签发）；② 外部 cycle ID 名义外部、签发方与被测同体（须 `issuer ≠ executor` 且故障域不同）；③ 传输 ack 与业务完成共用同一去重表或重试队列，上游重放会被下游读成「已完成」。共用同一输入快照即不满足独立，只能记 unverified，且「不独立」本身要落成一格、不折进健康分母。
补一格：**零匹配也要作为显式状态**，不得落成「无数据」，否则共享故障域的失败会伪装成「这一轮本来就没有」。
负例：共用源却记 `independent`。

### 13. 可携带判据最小三件与私有证据出桶（`portable_evidence`，检查项 U）

最小三件：**输入清单（可独立重放的输入标识）+ 产物指纹（内容哈希与大小，不带路径）+ 判据表达式（可脱离本机环境复算）**；缺任一件，该结论降级为**私有证据**并单独出桶计数，不得混进对外结论分母（否则会静默拉低那部分结论的可信度）。
环境固化与判据可携带是两笔账：环境线只进「本机自用」，不得把环境线的绿当成判据线的绿；凡判据验证路径必须经过原作者整套环境者，只记 `unverified`。
负例：三件缺一仍计入对外分母。

### 14. 覆盖度自检两条（`defect_coverage` / `repair_matrix`，检查项 V / W）

- **V 缺陷类覆盖**：8 类缺陷（静默改写 / 分母萎缩 / 声明当凭据 / 未观测当零 / 自报当证据 / 共享故障域 / 版本不可判 / 降级不可见）逐类须有检测入口，`classes[].detector` 与 `canon_guard.py` 实际检查项交叉校验，缺类或 detector 悬空一律判红。

## 工程口径吸纳层（v1.5.0，2026-09-30 续吸纳 3 组工序层口径）

承接 v1.4.0 的 23 项检查。本轮从 EigenFlux 2026-09-30 增量广播（20 条项目与工具类条目）中甄别出 3 组可直接落到本产线工序层的口径：机器可读真源 `config/engineering_canons.json` 升 **1.2.0**（adoption_map 21→24 条），校验器 `scripts/canon_guard.py` 的 `CHECKS` 由 A–W（23 项）扩至 **A–Z 共 26 项**，夹具 `tests/fixtures/canons/` 重新生成（正例 1 + 负例 26）。**存量真源（`param_contract.json` / `canonicalization.json` / `frozen_baseline.json` / `observability_rules.json` / `negcontrol_cases.json` 及各 `*.py`）字节级未动。**

### 1. 画质修复链路顺序不可交换与生成式重建声明（`restoration_chain_order`，检查项 X）

来源：EigenFlux 广播 `item_id 363370951368245248`（LTX 2.5 两门控 LoRA：Restore Details / Refine Details，480 线扫描素材修复）。

- **阶梯固定**：去隔行 → 修复 → 细节重建，顺序**不可交换**；先做细节重建，后续只能去修被强化的瑕疵。
- **进 guide 前禁止去噪 / 锐化**（含混合去隔行）：损伤被先锐化后更难去除，同时压低颜色推断的可用信息。
- **修复类产物是解释性重建、不是素材原貌**：须带声明（`AI 重建，非历史记录`）；重建出的文字 / 人脸 / 物体不得当作原始证据引用。
- **增益上限**：480 线素材约 **9×**（≈5760×4352）达峰，再高反效，超限判 `WARN`。
- **采样器族约束**：分块融合只允许离散族（`euler` / `heun` / `dpm_2`），**禁用**历史族（`dpmpp_2m` / `lms`）、自适应族、祖先族——失效形态分别是丢多步记忆、无法融合、逐块独立加噪必生接缝；违反判 **hardstop**。
- 负例：`refine` 排在 `restore` 之前 / 未去隔行直接进 guide / 对禁用族放行 → 必须判红。

### 2. 分块产物的接缝与闪烁「本应不存在」断言（`tile_seam_integrity`，检查项 Y）

- 「渲染无报错」不是产物合格的证据：分块产物必须带**本应不存在型**断言（`no_seam_on_tile_boundary` / `no_per_tile_flicker`），否则接缝与逐块闪烁会静默通过。本条与 §S 失败域分桶「断言集须留一条本应不存在」同源，此处落到具体工序。
- 块尺寸须落在训练桶内（restore 960×544 / refine 1024×576，块间重叠 0.5、融合方差 0.05），**越桶即视为编造纹理**，判 `FAIL`。
- 单块直出仅在输出尺寸本身等于训练桶时放行。
- 窗口档位 49 / 97 帧；超窗须走流式，否则丢细节、颜色漂移；guide **不得**使用空间 tiled 编码（网格会被印进条件）。
- 负例：缺接缝断言 / 越桶只警告 / guide 用 tiled 编码 → 必须判红。

### 3. 分段转写静默失败与句边界完整性（`asr_segment_silence`，检查项 Z）

来源：Noteknot（`item_id 363249621192933376`）与 Tiki（`item_id 363418658564734976`）的长视频 ASR 三步法（双引擎对齐 + 边界元数据 + 干跑基线）。

- **静默失败**：分段「非空 ≠ 完整」；须三数同行——声明总时长 / 实际转写覆盖时长 / 显式跳过段数（带原因码），缺任一判 `UNKNOWN`，不得判通过。
- **边界可回溯**：每个分段 / 章节边界须带 `source_event_id`，完整性声明与游标签发同源；不可回溯的覆盖声明降级为**私有证据**并单独出桶（对接 §U）。
- **句截断独立断言**：首句与末句须完整；只看分段非空无法暴露长视频常见的句尾截断，违反判 `FAIL`。
- **双引擎须独立**：交叉对齐的两引擎不得共用同一解码上游，否则记 `unverified`（对接 §T 共享故障域反例）。
- 另需相邻分段去重断言（防服务端重放）与干跑基线检查（检出编码 / 容器漂移）。
- 负例：只报分段条数不报三数 / 共享解码上游的双引擎仍记 `independent` → 必须判红。

### 1. 降级态双写与账本缺失硬停（`degrade_double_write`，检查项 AA）

来源：AI-Film-Studio 私信对拍（降级态双写两层键 + 账本字段缺失处置）。

- **两层键**：降级态须同时写在**命名层**（产物命名 / 标记）与**账本层**（结构化字段）上，两层写的是**同一个降级键**；只写一层不足以成立降级态。
- **账本权威**：账本层是降级态的唯一权威来源；**账本字段缺失 ⇒ 视为未声明降级态 ⇒ 硬停**。

### 2. 版本交叠判 AMBIGUOUS 交人工（`version_overlap_ambiguous`，检查项 AB）

- **交叠态三值**：`SINGLE` / `DISJOINT` / `AMBIGUOUS`；两版在交叠区间同时生效、且各自**生效起点不可判**时判 `AMBIGUOUS`，进人工裁决队列（`human_required`）。
- **禁止自动消歧**：显式禁止 `later_issuer_wins`（后签发者优先）、`timestamp_latest_wins`、`version_string_order` 三类序关系自动定版——「谁更新」与「谁生效」是两笔账。

### 2. 画面文字节奏地板（`hyperframes_type_rhythm_floor`，检查项 AL）

来源：`typeset.md`（正文行宽 45–75ch、1rem 下限、tabular 数字、字距下限 -0.04em）+ `craft-floor.md`。

- **五角色字号地板与步进**：`hook > heading > body > label > meta` 降序，相邻步进不小于 **1.25 倍**（层级不可辨即判红）。物理像素地板按竖屏折算：hook 64px / heading 48px / body 32px / label 25px / meta 20px。

- **行宽上限**：正文每行汉字数上限 **14 字**（由竖屏安全区宽度 1080×0.86≈928px 反推，非上游 ch 值照搬）；超限判 REJECT，**一律改版式（换行 / 降字数 / 分屏），不接受缩小字号换取容装**。

- **字体与数字**：仅打包实际用到的字重；回退字体须度量兼容且不造成回流位移；计数动画、比分、榜单等数字画面须 `tabular-nums`（避免逐帧跳宽）。

- **负例**：把「字够大」当唯一达标——标题 48px 而次级 46px（步进 1.04）、字距收到 -0.08em、深底直接套浅底行高字重、关键数字压进底部字幕区，任一即 REJECT。

### 3. 画面动效署名与可达性（`hyperframes_motion_authorship`，检查项 AM）

来源：`animate.md`（时序 / 缓动 / 可达性）+ `craft-floor.md`「署名的动效时刻」。

- **一镜一署名时刻**：整镜只允许一处「署名动效时刻」（标题逐字上浮 / 关键数字计数 / 主视觉入场，取其一），其余动效降为状态反馈级；多处强动效互相抵消注意力，超过 1 处判 REJECT。
- **时长四档且不得越档、不得重叠**：feedback 100–150ms / state 180–260ms / layout 280–420ms / focal 450–900ms。
- **缓动族**：主缓动 `cubic-bezier(0.16, 1, 0.3, 1)`；禁用 `bounce` / `elastic` / `back` 族——竖屏短视频已有平台侧节拍，画面内弹跳歧义且显廉价。
- **退出快于进入**：退出时长 ≤ 进入时长的 **0.7 倍**。
- **默认可见（硬性）**：HTML 默认渲染态即完整帧，GSAP 仅作增强；脚本 404 / 报错时画面必须依然可读，否则判 REJECT。
- **只动合成层属性**：允许 `transform` / `opacity` / `filter`；动 `width` / `height` / `top` / `left` / `margin` / `padding` 判 REJECT（逐帧重排掉帧、缩放态文字糊边）。
- **GSAP 约束**：单镜一个 timeline，seek 到任意时间点画面自洽（`timeline_atomic`），不得出现 `immediateRender` 造成的首帧错位；逐项错峰不超过 6 项、步长 40–90ms。
- **reduced-motion 降级路径**：必须提供 `@media (prefers-reduced-motion: reduce)` 降级，退化为**信息完整的静态定格帧**（无位移、无逐字上浮），不得退化为空屏或半帧。
- **负例**：一镜里标题上浮 + 数字计数 + 卡片依次弹入（3 处署名时刻）、用 back/elastic、时长越档拖到 1.5s、动 width/top 做位移、脚本失败即白屏或无 reduced-motion 降级——均判 REJECT。

### 4. 画面颜色角色与深度分层（`hyperframes_color_depth_roles`，检查项 AN）

来源：`colorize.md`（WCAG AA 对比度、OKLCH 优先）+ `craft-floor.md` 深度规则 + `layout.md` 分组邻近。

- **四色角色语义分工**：`surface`（底色/容器背景，不承担语义）/ `ink`（正文标题图标主色）/ `accent`（唯一强调色）/ `warn`（警示异常，与 accent 语义不可互换）；同帧强调色分工**不超过 2 类**，超出判 REJECT（多色强调等同没有强调）。

### 3. 锚点准入分层（本层的关键设计）

| 类别 | 断言内容 | 适用产物 | 反例 |
|---|---|---|---|
| **anchored** | 内容同一（字节数 + sha256） | 确定性产物（成片、清单、QR 报告等） | 任何改动都应判红 |
| **volatile** | **仅解码字节数**（`content_identity = not_asserted`） | 含 wall-clock 字段（`generated_at`）的例行留档 | 截断 / 字节数漂移判红；内容微改不判红 |

两层**必须互不交集**（自检 `anchor_admission_disjoint` 硬校验）；对 volatile 产物强行断言内容同一 → 直接 FAIL（`volatile_artifact_asserted_content_identity`），防止「准入分层」被误用为「跳过校验」。
